# `memento doctor --report`: 환경과 오류 집계를 이슈 초안으로 만든다

- 상태: 채택 (2026-11-19)
- 이슈: #1769
- 관련: #1768(로컬 사용 집계, `docs/adr/2026-11-18-issue-1768-local-usage-aggregate.md`), `docs/DIRECTION.md`

## 맥락

Memento 는 npm 에 공개되어 있어 주인 설치 두 곳 밖의 환경에서 깨지는 일을 주인이 알 길이 없다. 사용 정보를 자동으로 바깥에 보내는 방식(켜짐/꺼짐, 받는 서버)은 신뢰 비용과 운영 비용이 크고 외부 사용자가 적어 얻는 자료가 작다는 설계 보고서의 결론에 따라 택하지 않았다. 사용자가 문제를 겪고 이슈를 올리기로 했을 때 보고하기 쉽게 하는 것까지만 한다.

## 결정

1. **보고서 모양은 `UsageReport` 한 타입이다.** 모든 칸이 열거값, 구간, 정해진 모양의 숫자와 버전이다. 자유 문자열 칸이 없다. #1768 의 어휘(`usage-vocabulary.ts`)를 그대로 쓴다. 클라이언트 이름은 알려진 목록 또는 `other`/`unknown`, 도구는 등록된 이름 또는 `other`, 오류 코드는 허용 목록 7개다.
2. **칸을 하나씩 채운다.** `buildUsageReport` 가 입력 칸마다 정규화해 새 객체를 만든다. 입력을 펼쳐 넣지 않는다. 출력 직전에 `validateUsageReport` 가 키와 값의 모양을 다시 확인하고, 어긋나면 아무것도 출력하지 않고 실패한다.
3. **칸 목록.** 보고서 버전, Memento 버전(major.minor.patch), Node 주 버전, OS(`linux|darwin|win32|other`), CPU(`x64|arm64|other`), 설치 방식(`npm-global|npx|docker|source|unknown`, 경로로 분류만 하고 경로는 쓰지 않는다), 임베딩 제공자(알려진 5개 또는 `other`), 기억 수 구간(`0|1-99|100-999|1000-9999|10000+|unknown`), 네이티브 모듈 적재 여부(`ok|load_failed`), DB 상태(`ok|missing|open_failed`), 스키마 버전, 최근 7일 요청 수와 오류 수, 클라이언트별 요청/오류(다섯 줄), 오류가 난 도구와 코드별 횟수(다섯 줄).
4. **네이티브 모듈 적재는 메모리 DB 로 따로 확인한다.** better-sqlite3 는 첫 `new Database` 때 네이티브 모듈을 적재한다. 그래서 DB 파일 문제와 적재 실패가 구분되도록 `:memory:` 로 먼저 열어 본다. 적재가 실패해도 보고서는 만든다. 그때 DB 칸은 `open_failed` 로 둔다.
5. **DB 는 읽기 전용으로 연다.** `memory_item` 개수와 `usage_daily_count` 의 최근 7일 합계, 스키마 버전만 읽는다. 열기만으로는 SQLite 파일인지 알 수 없어 첫 질의로 확인한다.
6. **링크는 출력만 한다.** 열지 않고 어떤 네트워크 호출도 하지 않는다. 본문이 2,048바이트를 넘으면 링크 없이 복사용 출력만 낸다(URL 길이 한도가 문서에 없어 보수적으로 잡았다). 가장 큰 보고서도 이 한도 안이다(테스트).
7. **제목은 `[환경 보고] memento <버전>`, 라벨 파라미터는 붙이지 않는다.** 저장소에 라벨을 매길 권한이 없는 사용자는 파라미터가 무시되는지 문서로 확인하지 못했다. 분류는 제목 접두사로 한다.
8. **안내 한 줄.** 서버 시작 실패, 마이그레이션 실패(신규/기존 DB), 시작 실패 FATAL 메시지 끝에 `DOCTOR_REPORT_HINT` 를 붙인다. 한 줄이 한 상수라 문구를 바꾸기 쉽다.
9. **기존 `doctor`(Agent endpoint 진단)와 갈라 둔다.** `--report` 가 있을 때만 새 경로로 가고, 없을 때의 동작은 바뀌지 않는다. 새 경로는 endpoint 해석이나 서버 호출을 하지 않는다.

## 하지 않는 것

- 자동 전송, 동의 방식 전송, 받는 서버. 외부 보고가 석 달에 3건을 넘고 보고마다 환경이 달라 패턴을 못 잡으면 동의 방식을 다시 검토한다(이슈 본문).
- 오류 메시지와 스택, 로그, 설정 덤프, 환경 변수를 싣는 것. 사용자가 이슈 본문에 직접 붙이는 것은 사용자의 몫이다.

## 알려진 한계

- `usage_daily_count` 의 `tool` 칸 제약은 모양만 본다. 보고서는 읽을 때 등록된 도구 목록으로 다시 거른다.
- 설치 방식은 모듈 경로로 추정한다. 심볼릭 링크나 사설 래퍼를 쓰면 `unknown` 이다.
