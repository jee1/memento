# Jev 관계 판정 개선과 탐색 평가 (#1470)

## 결과와 해석 범위

2026-10-24 공유 `JevRelationJudge`의 맥락·후속·대조·의존 질문 네 곳을 구체화했다. remember와 `RelationExtractor`가 같은 수정 경로를 쓴다. 후보 풀, 점수 임계값 0.5, API·설정·export는 유지했다. 추가 라운드나 새 의존성은 없다.

사용자가 [합성 평가표](../../tests/fixtures/jev-relation-quality/README.md)를 제시받은 뒤 “진행해줘.”로 구현 진행을 승인했다. 이는 개별 정답을 사람이 직접 검토했다는 증거가 아니다. [평가 입력](../../tests/fixtures/jev-relation-quality/pairs.json)은 `accepted`, 결과는 `human_reviewed: false`로 구분한다. 아래 수치는 **사용자가 수용한 합성 정답에 대한 탐색 평가**다. #1470의 사람 gold 검증 완료를 주장하지 않는다.

28쌍 중 관계 20쌍·무관 4쌍을 주 지표에 사용하고, 근거가 부족한 4쌍은 사전에 `ambiguous`로 제외했다. 평가 쌍·종류·이유는 기준선 이후 바꾸지 않았다. [공개 집계·출처](../../tests/fixtures/jev-relation-quality/measurement-2026-10-24.json)에 입력 SHA, 실행 코드 SHA, 모델, 시각, 전후·반복 결과를 남겼다. private 기억 원문·ID는 포함하지 않는다.

## 원인과 최소 변경

기존 맥락 질문은 같은 단어를 가진 다른 대상의 기록을 통과시켰다. 짧은 종류 질문은 시간 인접·내용 반복을 후속으로, 다른 대상의 템플릿·수치 차이를 대조로 받아들였다. 최댓값을 선택하는 공유 경로에서 높은 종류 점수가 그대로 채택됐다.

- 맥락: 같은 **구체적 작업 흐름이나 사건**의 연결을 묻는다.
- FOLLOWS: 같은 흐름의 사건·단계가 target 뒤에 발생·실행되는지 묻는다. 인과는 요구하지 않으며 저장 순서·내용 반복·무관한 시간 인접을 제외한다.
- CONTRASTS_WITH: 같은 대상·비교 축에서 다른 주장·선택지·조건을 대조하는지 묻는다. 반복·동급 작업·단순 후속을 제외한다.
- DEPENDS_ON: 단순 참조와 필수 전제를 구분한다. 대상 두 종류만 고친 중간안에서 정상 의존 사례가 누락돼 이 설명 한 곳도 보완했다.

첫 수정안의 맥락 질문은 정상 단계 두 쌍까지 거절해 폐기했다. 의존 관계 회귀가 남은 두 번째 안도 최종안으로 채택하지 않았다. 후보 풀·임계값을 조절하거나 사후에 정답을 바꿔 수치를 맞추지 않았다. 이 집합에서 질문을 수정했으므로 독립 holdout 결과는 아니다.

## 사전 고정한 기준과 실측

수정안 실행 전에 다음 기준을 고정했다. 두 대상 종류의 precision 각각 0.8 이상과 잘못된 채택 합계 최소 1건 감소, 무관 채택 감소(이미 0이면 유지), 전체·대상 두 종류·REFERENCES 누락률 증가 없음, CAUSES·DEPENDS_ON·BELONGS_TO의 올바른 채택 감소 없음, 거절률 증가 최대 0.15, 오류율 0이다.

모델은 모든 실행에서 `jev-latest`, 시간 제한 10초다. 실제 공유 `judge(source, [target])`를 쌍별로 호출했다. 기준선은 수정 전 보관 소스(HEAD와 일치)를 별도로 컴파일해 실행했다. 수정안은 현재 빌드에서 실행했다. 같은 HEAD의 미커밋 변경이므로 실행 JS의 SHA를 별도로 기록한다. `accepted` 메타데이터로 바로잡은 뒤 같은 입력 바이트로 기준선·수정안·반복을 모두 다시 실행했다. 이전 예비 실행은 최종 집계에 섞지 않았다.

## 평가 규칙과 재실행

공개 [관계 타입 표준](../reference/ko/relation-type-vocabulary.md)과 [라벨링 가이드](../guides/ko/relation-labeling-guide.md)를 따른다. 방향은 source → target이다. 복수 종류가 타당하면 허용 목록에 모두 기록하며 그중 하나를 맞히면 누락으로 세지 않는다. `s01`·`s02`의 동급 작업, `a01`·`a02`의 대상 맥락 부족은 보류했다. 결과를 본 뒤 불리한 쌍을 보류로 옮기지 않았다.

`pending`은 실행·집계를 거절한다. 사용자가 실행을 수용한 입력은 `accepted_by`·`accepted_at`으로 `accepted`를 기록하고 탐색 결과로 표시한다. 실제 정답 검토는 `reviewer`·`reviewed_at`으로 `reviewed`를 기록한다. 메타데이터 자체는 사람 검토의 기술적 증명이 아니다.

```sh
npm run build -w @memento/core
node scripts/run-jev-relation-evaluation.mjs --fixture tests/fixtures/jev-relation-quality/pairs.json > .local/jev-evaluation/new-run.json
node scripts/evaluate-jev-relations.mjs   --fixture tests/fixtures/jev-relation-quality/pairs.json   --baseline .local/jev-evaluation/baseline-final.json   --candidate .local/jev-evaluation/candidate-3.json
```

실행기는 기존 `TYPESAFE_API_KEY`·모델 설정을 사용한다. DB에 접근하지 않으며 stdout에 snapshot을 쓴다. `ok`+`null`은 정상 거절, `error`+`null`은 모델 오류다. 모든 ID를 한 번씩 포함해야 하며 SHA 불일치·누락·중복·잘못된 종류·역방향 출력을 거절한다. 비교기는 출처를 기록하지만 수동으로 작성한 snapshot의 진위를 증명하지 않는다. 실제 실행에서는 질문·라운드별 점수를 로컬에 함께 보관했다.

precision은 올바른 종류 채택/해당 종류 채택, 누락률은 정답 쌍 중 어떤 허용 종류로도 맞히지 못한 쌍/정답 쌍이다. 오류도 참 관계 누락에 포함하고 오류율을 별도 표시한다. 분모가 0이면 `null`이다. 전부 거절하면 precision `null`, 참 관계 누락률 1이다. `ambiguous`는 모든 주 지표 분모에서 제외한다. 종류 오류는 잘못 예측한 종류의 precision과 정답 쌍의 누락 양쪽에 반영한다.

## 검증과 남은 제한

공유 질문 요청 테스트는 수정 전 실패를 확인한 뒤 수정 후 통과했다. 이 테스트는 요청 계약을 고정하며 의미 품질 증거는 위 실제 모델 평가다. 평가기·실행기·공유 판정·remember 경로의 최신 대상 테스트 44개가 통과했다. lint·타입 검사·`.mjs`를 명시한 ESLint도 통과했다. 최종 `npm test`는 638개 파일·6,338개 테스트가 통과했고 기존 2개 파일·36개 테스트는 건너뛰었다. 수정 중 실행한 검증에서 이전 질문 캐시와 새 assertion이 섞여 실패한 뒤, 변경을 멈춘 상태로 전체 검증을 다시 실행해 통과했다. graphify 재빌드도 완료했다(SQL 파서 부재·미지원 파일 경고는 기존 상태). 문서 링크와 JSON 출처 일치·private 본문 비포함도 확인했다.

사람이 개별 정답을 검토한 gold·평가자 일치도·별도 holdout은 남았다. 원래 #1466의 166쌍 private 판정 파일은 이 작업공간에서 찾지 못해 새 합성 집합과 새 읽기 전용 표본을 사용했다. recall 검색 품질 개선은 측정하지 않았다. #1470 전체 완료나 운영 정리 승인을 뜻하지 않는다.
