# System Prompt Pattern

이 문서는 **베어 MCP 모드**에서 외부 비서(OpenClaw / NanoClaw / ZeroClaw 등)에 Memento를 붙일 때 권장하는 시스템 프롬프트 패턴을 다룹니다.

베어 MCP 모드란 비서의 LLM이 Memento의 `recall` / `remember` 도구를 **자기 의지로** 호출하는 형태입니다. v0.2에서 제공될 `@memento/assistant` SDK는 이 호출을 자동화하지만, **v0.1은 베어 MCP만 제공**하므로 LLM이 부지런히 도구를 호출하도록 만드는 일은 전적으로 **시스템 프롬프트의 책임**입니다.

> "프롬프트가 곧 정책"이 v0.1의 운용 모델입니다. 비서 LLM이 새 주제마다 `recall`을 부르고, 사용자의 사실/선호/약속을 들으면 `remember`로 저장하도록 유도해야 합니다. 그 정책 문장이 아래 블록입니다.

트랜스포트 셋업과 토큰은 별도 문서에서 다룹니다 ([`./transports.md`](./transports.md), [`./auth.md`](./auth.md)).

## 권장 시스템 프롬프트 블록

아래 블록을 비서의 system 슬롯(또는 system prompt 파일)에 **그대로 붙여넣고** `<현재_채널>`·`<현재_사용자>` 자리만 비서별로 채우세요. 블록 본문은 의도적으로 짧게 유지되어 있으니, 임의로 문장을 풀어 쓰거나 항목을 빼지 마세요.

```text
[Memento Memory]
이 어시스턴트는 memento MCP 서버에 장기 기억을 저장합니다. 다음 규칙을 따릅니다:

1. 사용자가 새 주제를 꺼내거나 과거 사실/대화를 참조할 때, 우선 `memento.recall(query)`를 호출하여 관련 기억을 가져옵니다.
2. 사용자가 사실, 선호, 약속, 결정사항을 알려주면 응답을 마치기 전 `memento.remember`로 저장합니다. type 매핑:
   - 사실/지식 → `semantic`
   - 사건/대화/약속 → `episodic` (미래 약속은 tags에 'commitment' 추가)
   - 임시 컨텍스트 → `working` (48h)
3. 모든 저장은 다음 tags를 자동 부여: ["channel:<현재_채널>", "user:<현재_사용자>"]
4. recall 결과는 출처(memory_id, type, importance)를 응답에 명시하지 않아도 되지만, 사용자가 "어떻게 알았어?"라고 물으면 출처를 노출할 수 있습니다.

memento가 응답하지 않으면 **그냥 진행**하세요. 메모리는 augmentation이지 dependency가 아닙니다.
```

이 블록은 비서의 기존 system 프롬프트와 **결합**되도록 설계되어 있습니다. 페르소나·말투·금지사항 같은 다른 정책은 위·아래에 자유롭게 두고, 이 블록은 별도 섹션으로 보존하세요.

## 채널·사용자 태그 치환

`<현재_채널>`과 `<현재_사용자>`는 비서가 **이벤트 발생 시점에 실제로 채워야 하는 변수**입니다. 시스템 프롬프트에 박힌 정적 문자열로 두지 말고, 비서 측 어댑터가 메시지마다 적절한 값으로 렌더링하도록 만드세요.

| 토큰 | 의미 | 예시 값 |
|---|---|---|
| `<현재_채널>` | 메시지가 들어온 표면(surface). 채널·플랫폼 식별자. | `desktop`, `telegram`, `discord:guild123`, `slack:C0XXXX` |
| `<현재_사용자>` | 비서를 부른 사람의 안정적인 식별자. 가능하면 플랫폼 user id, 없으면 핸들. | `tg:1234567`, `discord:userid`, `local` |

비서별 권장 매핑·렌더링 위치는 각 비서 가이드 본문에서 다시 안내합니다.

- [OpenClaw 가이드](../openclaw.md): 데스크톱 단일 사용자, `channel:desktop` + `user:local` 정도가 흔한 기본값.
- [NanoClaw 가이드](../nanoclaw.md): 컨테이너에서 webhook으로 들어오는 채널·유저를 그대로 토큰으로 흘려보냅니다.
- [ZeroClaw 가이드](../zeroclaw.md): 24/7 봇이라 채널·유저가 메시지마다 달라지므로, 어댑터에서 동적 치환이 필수입니다.

> **왜 자동 태그가 중요한가**: `recall`은 기본적으로 모든 기억을 대상으로 검색합니다. 채널·사용자 라벨이 붙어 있어야 나중에 "텔레그램에서 했던 약속만" 같은 필터링이 가능합니다. v0.2 SDK가 도착하기 전까지는 이 태깅 책임이 시스템 프롬프트에 있습니다 ([`./transports.md`의 owner_id / 채널 태그](./transports.md#owner_id--채널-태그) 절도 함께 참고).

## type 매핑 가이드

Memento의 메모리 티어는 4종이며, 베어 MCP에서는 LLM이 매 저장마다 적절한 `type`을 직접 골라야 합니다. 시스템 프롬프트 블록의 매핑을 확장한 결정 가이드는 다음과 같습니다.

| type | 보존 정책 | 적합한 콘텐츠 | 부적합한 콘텐츠 |
|---|---|---|---|
| `semantic` | TTL 없음 (영구) | 사용자 이름·생년월일, 좋아하는 언어, 회사·직책, 반복 가능한 기술적 사실 | 일회성 채팅, 미래 약속, 단발성 이벤트 |
| `episodic` | 약 90일 TTL | 사용자가 한 말·결정·약속, 회의·통화 기록, 어제 무슨 일이 있었는지 | 변하지 않는 정체성 사실(→ `semantic`), 1시간만 유효한 작업 노트(→ `working`) |
| `working` | 48시간 TTL | "이번 세션 동안만 기억해 줘" 류 컨텍스트, 화면에 띄워둔 코드 스니펫, 임시 비밀번호 힌트 | 영속해야 하는 사실, 미래 약속 |
| `procedural` | TTL 없음 (영구) | "이런 요청이 오면 이렇게 처리하라"는 반복 절차, 비서 자체의 운영 룰 | 일반 채팅에서 거의 등장하지 않음 — 명시적으로 절차를 정의할 때만 사용 |

### 결정 휴리스틱

LLM이 헷갈릴 때 다음 순서로 자문하게 하세요(시스템 프롬프트에 추가로 넣어도 좋습니다).

1. **이 정보는 1주일 뒤에도 의미가 있는가?** 아니면 → `working`.
2. **이건 변하지 않는 사실인가, 한 시점의 사건인가?** 사실 → `semantic`, 사건 → `episodic`.
3. **이게 "이런 입력이 오면 이렇게 한다" 류의 룰인가?** → `procedural` (드물게).

### `procedural` 티어에 대한 주의

`procedural`은 일반적인 대화 저장소가 아닙니다. "사용자가 'X' 슬래시 명령을 치면 비서는 Y를 한다" 같은 비서 자체의 운영 절차를 명시할 때만 쓰세요. 평범한 채팅에서는 거의 등장하지 않으므로, 시스템 프롬프트의 결정표에서는 의도적으로 빠져 있습니다. 고급 사용자가 절차를 명시적으로 등록할 때만 LLM이 이 티어를 고르도록 별도 룰을 추가하세요.

## ExtractedItem 추출 패턴

베어 MCP에서는 **LLM이 사용자의 발화에서 무엇을 저장할지 직접 추출**해야 합니다. 추천 형태는 세 종류로 좁히면 충분합니다.

| kind | 의미 | 적합한 type | 예시 발화 |
|---|---|---|---|
| `fact` | 객관적 사실/지식 | `semantic` | "내 형은 의사야", "프로젝트 이름은 Memento야" |
| `preference` | 선호·성향 | `semantic` | "나는 한글로 답변받는 게 편해", "다크 모드를 좋아해" |
| `event` | 사건·대화·약속 | `episodic` | "어제 PR을 머지했어", "내일 3시에 회의 잡았어" |

### 짧은 예시

사용자가 "다음 주 화요일에 치과 예약 잡아 둘게"라고 말한 경우 LLM이 다음과 비슷한 호출을 만들면 됩니다.

```jsonc
// memento.remember
{
  "content": "사용자가 다음 주 화요일에 치과 예약을 잡을 예정이라고 말함",
  "type": "episodic",
  "tags": ["channel:telegram", "user:tg:1234567", "commitment"]
}
```

사용자가 "나는 vegetarian이야"라고 말한 경우.

```jsonc
{
  "content": "사용자는 채식주의자(vegetarian)임",
  "type": "semantic",
  "tags": ["channel:desktop", "user:local", "preference"]
}
```

### `commitment`는 별도 kind가 아니다

미래 약속(commitment)은 자주 등장하지만, **별도의 ExtractedItem kind로 두지 않습니다**. 이유는 단순합니다 — 약속도 "어떤 시점에 있었던/있을 사건"이므로 `event`(= `type: episodic`)의 한 종류이고, 그 위에 라벨을 얹는 편이 데이터 모델을 단순하게 유지합니다.

규약은 다음과 같습니다.

- **kind**: `event` (= `type: episodic`)
- **tags**: 기본 태그(channel·user)에 더해 `'commitment'`를 추가

이렇게 두면 나중에 "남은 약속 보여 줘" 같은 검색을 `recall`의 태그 필터로 처리할 수 있습니다. 시스템 프롬프트 블록의 "미래 약속은 tags에 'commitment' 추가" 한 줄이 이 규약을 LLM에게 강제하는 부분입니다.

## recall 출처 노출 정책

`recall`은 결과마다 `memory_id`, `type`, `importance`(또는 score)를 함께 돌려줍니다. 이를 **응답에 항상 보여 줄지**가 한 가지 결정 포인트입니다.

**기본값은 silent**: 비서는 회상한 내용을 **자연스러운 문장에 녹여서만** 답하고, memory_id 같은 메타데이터는 노출하지 않습니다. 시스템 프롬프트 블록 4번 항목이 이 기본값을 정의합니다.

예외:

- 사용자가 "어떻게 알았어?", "이거 어디서 들은 거야?", "그 출처 보여 줘" 같이 **명시적으로 요청**하면 노출합니다. 이때는 `memory_id`와 저장 시점, `type`을 짧게 보여주는 정도면 충분합니다.
- 디버깅 모드(예: 개발자 명령어 `/why`)에서는 토글로 출처를 항상 노출하도록 만들 수 있습니다 — 단, 이는 비서의 부가 기능이지 기본 정책은 아닙니다.

> 항상 출처를 노출하면 회상의 가치가 빠르게 떨어집니다 — 채팅이 메타정보로 도배됩니다. silent를 기본으로 두고, 사용자가 물어볼 때만 보여주는 편이 사용자 경험에 더 좋습니다.

## 실패 시 동작

Memento는 **augmentation**이지 **dependency**가 아닙니다. 서버가 죽었거나 네트워크가 단절돼도 비서는 평소처럼 답해야 합니다.

권장 정책:

1. `recall` / `remember`가 5xx, timeout, 또는 connection error로 실패하면 **호출이 없었던 것처럼 그대로 진행**합니다.
2. 회상 결과 없이 답하더라도 **사용자에게 거짓 진술을 하지 않습니다**. 특히 다음 같은 표현은 금지입니다.
   - "기억나지 않아요" / "전에 말씀하신 적 없어요" — 회상 자체가 실패했을 때 이렇게 답하면 사용자에게 거짓 정보를 줍니다.
   - "메모리에 없어요" — 메모리에 없는지 진짜로 검증하지 않은 채 단정하지 마세요.
3. 사용자가 명시적으로 "그거 기억해 둬"라고 했는데 `remember`가 실패했다면, **저장에 실패했다는 사실을 솔직히 알리고** 사용자가 다시 시도할 수 있게 합니다. (예: "지금 메모리 서버 응답이 없어서 저장하지 못했어요. 잠시 후 다시 알려주실래요?")

세부 트러블슈팅(401, 503, 검색 결과 비어 있음 등)은 [`./troubleshooting.md`](./troubleshooting.md)에서 다룹니다.

## 한 단계 더: `@memento/assistant` 사용 시

SDK가 매 턴 `<memento>...</memento>` 펜스 블록을 자동으로 만들어 시스템 프롬프트에 합성합니다.
이 경우 위의 권장 프롬프트는 *짧아져도* 됩니다 — recall 호출 의지를 LLM에 부탁할 필요가 없으니까요.

권장 SDK용 시스템 프롬프트:
```
당신은 사용자의 개인 비서입니다. 시스템 프롬프트에 포함된 <memento>...</memento> 블록은
이 사용자에 관해 이전에 알게 된 사실/선호/사건의 회상입니다. 답변에 적극 활용하세요.
없으면 그냥 답변하세요.
```

자동 저장 정책 옵션은 [`./sdk-quickstart.md`](./sdk-quickstart.md) 참조.
