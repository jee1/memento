## 1. 비즈니스 목표


| 목표           | 설명                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------- |
| **시그널 전달**   | Memento를 쓰는 LLM(에이전트)이 “기억 품질 문제가 있다”는 시그널을 **기존 도구 응답**을 통해 받고, 필요 시 상세 요약·도구를 호출하도록 한다.           |
| **자기 성찰 활용** | 에이전트가 저신뢰·고실패 메모리 요약을 보고 사용자에게 경고하거나, 실패 회피 규칙을 참고해 제안할 수 있게 한다.                                    |
| **규칙 보관**    | 실패 회피 규칙을 Memento가 저장·조회하게 하여, 외부 LLM이 “제안”을 만들 때 규칙을 회수할 수 있게 한다. (규칙 추출은 외부 LLM, 저장·조회는 Memento.) |


---

## 2. 사용자(시스템·에이전트) 여정

- **여정 1 — recall / get_meta_memory_stats 호출**: 에이전트가 기억을 조회한다.  
→ 응답에 **introspection_hint**가 포함될 수 있다(저신뢰·고실패가 1건 이상일 때).  
→ 에이전트는 힌트를 보고 “get_introspection_summary 호출 권장”을 인지한다.
- **여정 2 — get_introspection_summary 호출**: 에이전트가 상세 요약(저신뢰·고실패 건수, 요약 문장, ID 목록)을 요청한다.  
→ Memento는 **스케줄 기반 캐시**된 최근 스캔 결과를 반환한다.  
→ 에이전트는 이 정보를 컨텍스트에 넣어 사용자에게 경고하거나, 다음 행동을 결정한다.
- **여정 3 — 실패 회피 규칙 저장·회수**(Phase B 후반): 외부(클라이언트) LLM이 고실패 메모리 내용을 분석해 “실패 회피 규칙” 문장을 만든다.  
→ 클라이언트가 Memento에 **규칙 저장** 도구를 호출해 규칙을 등록한다.  
→ 에이전트가 요약·제안을 할 때 **저장된 규칙**을 조회해 “이런 상황에서는 … 하지 마라” 식의 제안에 활용한다.

---

## 3. 성공 기준 (비기술)

- **recall** 또는 **get_meta_memory_stats** 응답에, 저신뢰/고실패가 있을 때만 **introspection_hint**가 포함된다.
- 에이전트가 **get_introspection_summary** 도구를 호출하면 **캐시된 스캔 결과**(요약·건수·ID 목록)를 받을 수 있다.
- 스캔은 **실시간이 아니라 스케줄(meta_memory_introspection job) 기반**이며, 캐시는 해당 job 실행 결과로 갱신된다.
- (선택) 실패 회피 규칙을 Memento에 **저장·조회**할 수 있어, 외부 LLM이 제안 시 규칙을 회수할 수 있다.
