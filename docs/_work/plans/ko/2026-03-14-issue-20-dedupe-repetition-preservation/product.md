# 이슈 #20 — Memory Bank: Product

SDD **Plan** 단계의 **Memory Bank** 문서 3/3. 비즈니스 맥락·기존 기능과의 연관을 정리한다.

---

## 1. 제품 관점

- **저장 효율**: 유사 기억이 많아질수록 디스크·스캔 비용이 커짐. 병합으로 행 수를 줄여 비용을 관리한다.
- **기억 품질**: “자주 반복된 기억”은 에이전트·사용자에게 더 중요한 정보일 가능성이 높다. 반복 정보를 보존해 recall 품질을 높인다.
- **정책 일관성**: #20을 “단순 삭제”가 아니라 “반복 보존 + 저장 최적화”로 정의해, Memori 계열(#89·#90)과 방향을 맞춘다.

---

## 2. 기존 기능과의 연관

| 기능 | 연관 |
|------|------|
| **remember** | 변경 없음. 즉시 1건 저장. 병합은 워커에서만 수행. |
| **recall** | #88 boost가 적용되면 “반복된 기억”이 더 잘 노출됨. 본 기능은 병합 시 메타를 채워 주어 그 효과를 낸다. |
| **#88 Fact 메타** | num_times, last_mentioned_at 공급자. 본 기능은 해당 메타를 “병합 시 갱신”하고 “recall 시 사용”되도록 연동. |
| **#89 비동기 Augmentation** | 워커가 중복 제거·압축을 수행하는 위치. 본 기능은 “병합 시 num_times·last_mentioned_at 갱신”을 워커 단계에 포함. |
| **#90 Triples/KG dedupe** | memory_item 수준 병합 정책과 정합(유사도·대표 선정 등). KG 전용 dedupe는 #90, 본 기능은 memory_item + 반복 보존. |

---

## 3. 목표 사용자·시나리오

- **에이전트/시스템**: 동일·유사 내용을 여러 번 remember 하는 경우, 저장은 줄이되 “중요도”는 유지되어 recall 시 더 잘 나오게 함.
- **운영/분석**: (선택) 병합 이력(merged_into_id, soft-delete)으로 “어떤 기억이 하나로 묶였는지” 추적 가능.
