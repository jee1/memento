## 1. 배경

Wave 3는 핵심 경로의 `any` 남용을 줄여 **런타임 안전성**과 **리뷰 가능성**을 높인다. 로드맵에 따라 착수 시점에 **우선순위 파일 목록을 린트로 재확정**한다.

브레인스토밍에서 **범위 고정 방식**으로 다음을 채택했다.

- **`*.spec.ts`는 이번 PR에서 제외** (테스트 전용 타입 정리는 후속 PR·이슈로 분리).
- **`@memento/core`의 배포·런타임 경로 우선**; 우선순위는 **`npm run lint`의 `@typescript-eslint/no-explicit-any` 위반**을 파일 단위로 집계해 상위 **K개(기본 3~5)**만 PR1에 포함.

---

## 2. 목표

- PR1에서 다루는 모듈에서 `any`를 **`unknown` + 가드**, **좁은 인터페이스·DTO**, **제네릭** 등으로 치환하여 의미 있는 타입 경계를 만든다.
- 동작 변경 없이 **타입 정보만 강화**하는 것을 원칙으로 한다 (런타임 계약이 바뀌면 설계·테스트에 명시).

### 2.1 완료 조건 (이슈 #216과 동일)

- `npm run lint`
- `npm run type-check`
- `npm test`

---

## 3. 범위 (PR1)

### 3.1 포함 (화이트리스트)

`packages/memento-core/src` 아래에서, 실제 서버·라이브러리 실행 경로에 해당하는 코드:

- `domains/`
- `infrastructure/`
- `shared/`
- (해당 시) 패키지 루트의 `tools/` 등 **런타임에서 import되는** 유틸

### 3.2 제외

- 모든 `**/*.spec.ts`
- **`packages/memento-core/src/test/**`** — 스펙이 아니더라도 테스트 하네스·픽스처로 PR1의 “프로덕션 우선” 범위에서 제외한다.
- DB 스키마 변경, 마이그레이션 형식 변경, CI 슬롭 하드 게이트 도입 (이슈·로드맵 비목표).

### 3.3 `memento-server`

- **권장**: PR1은 **`@memento/core`만** 머지하고, 서버 쪽 `any`는 **후속 PR**로 분리한다.
- **대안**: 동일 PR에 서버 파일을 **최대 1~2개**만 포함할 수 있다. 이 경우에도 Wave 1·2와 **동일 파일을 동시에 편집하지 않는다**.

---

## 4. 우선순위 확정 절차 (착수 시 필수)

1. 위 **3.1 화이트리스트** 경로에 한해 `npm run lint`를 실행한다 (로컬·CI와 동일한 ESLint 구성).
2. `@typescript-eslint/no-explicit-any` 위반을 **파일 경로별 건수**로 집계한다 (`eslint` JSON 포맷 등으로 자동화 가능).
3. **제외 규칙(3.2)**을 적용한 뒤, 건수 상위에서 **K개(기본 3~5, 필요 시 PR 설명에서 K 명시)**를 PR1 대상으로 확정한다.
4. 확정 목록을 PR 본문에 **불릿으로 고정**하고, 구현 중 범위 변경이 있으면 리뷰어 합의 하에만 조정한다.

착수 전 **grep 기반 휴리스틱**은 보조일 뿐이며, **최종 우선순위는 ESLint 출력**으로 한다.

---

## 5. 타입 치환 가이드

- 외부 입력·DB row·JSON: `unknown` 수신 후 **가드·파서·Zod(이미 쓰는 곳은 기존 패턴)**으로 좁힌다.
- 내부 private 필드 접근이 테스트에서만 필요한 경우: PR1 범위에서 **프로덕션 파일만** 다루므로, **테스트용 `as any`는 파일 밖으로 미룬다** (별도 웨이브).
- `eslint-disable-next-line @typescript-eslint/no-explicit-any`는 **불가피한 경우에만** 사용하고, **한 줄 주석으로 근거**를 남긴다.
