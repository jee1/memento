# 설계: 이슈 #175 — `bootstrap` 초기화 검증 우선·조건부 얇은 분리

**상태**: 브레인스토밍 확정 (구현 전)  
**날짜**: 2026-05-01  
**관련**: [GitHub #175](https://github.com/jee1/memento/issues/175), 선행 분할 스펙 [#214 Wave 1](https://github.com/jee1/memento/issues/214) (`docs/superpowers/specs/2026-05-01-issue-214-wave1-bootstrap-design.md`)

---

## 1. 목적

이슈 #175에서 보고된 **`initializeServices` 단일 함수 과대·고복잡도** 문제가 **현재 `main` 기준으로 재현되는지**를 먼저 검증하고, 도구나 리뷰에서 여전히 `initializeServices`(또는 동일 오케스트레이션)가 병목으로 지목될 때만 **추가 분리(얇은 조립 함수)** 를 적용한다. 런타임 동작·`ServerServices` 공개 계약은 변경하지 않는다.

---

## 2. 배경·현재 상태

- #175 본문은 과거 스냅샷 기준으로 `initializeServices` 약 259줄·순환 복잡도 33 등을 지적한다.
- **Wave 1(#214)** 에 따라 초기화는 이미 `packages/memento-core/src/bootstrap/*.ts` 모듈로 분리되었고, 루트 `bootstrap.ts`는 주로 **이름 있는 팩토리 호출 + 반환 객체 조립**을 담당한다.
- 따라서 본 작업의 핵심은 “다시 한 파일에 모으기”가 아니라 **지표 재측정 → 필요 시 마지막 한 겹만 정리**이다.

---

## 3. 범위

| 포함 | 제외 |
|------|------|
| **A.** `packages/memento-core/src/bootstrap.ts` 및 `bootstrap/**/*.ts`에 대한 복잡도·정적 분석 **재실행·결과 기록**(이슈 또는 PR 본문에 요약) | `bootstrap/` **내부**의 광범위 리팩터를 한 이슈에 일괄 포함하는 것(C 범위 전체). 새 병목은 **별도 이슈**로 쪼갠다. |
| **B.(조건부)** 도구 또는 페어 리뷰에서 `initializeServices`만 여전히 과대하다고 판단될 때: 반환 객체 조립을 **`assembleServerServices(...)` 등 순수 조립 헬퍼**로 이동하고, `initializeServices`는 비동기 단계 호출만 남긴다. | DB 스키마·`initializeDatabase`·도메인 서비스 동작 변경 |
| 계약 유지: `initializeServices(db)` 시그니처, 초기화 **순서**, `ServerServices` 필드 구성 | 기능 추가, 새 전역 싱글톤 |

## 4. 단계별 접근

### 4.1 단계 A — 검증 우선 (항상 수행)

1. 로컬에서 **이슈 #175 작성 시 사용한 것과 동일한 분석 파이프라인**이 있으면 그대로 재실행한다. (저장소 내 다른 이슈에서는 `ai-slop-detector --js` 등이 언급되나, 패키지명·설치 경로는 팀 환경을 따른다.)
2. 동일 도구를 쓸 수 없으면 **대체 검증**으로 다음을 수행하고 결과를 PR/이슈에 남긴다.
   - `wc -l` 등으로 `bootstrap.ts`·`bootstrap/*.ts` **라인 수 추이** 기록.
   - `initializeServices` 본문이 **오케스트레이션만**인지(분기·중첩 최소) 코드 리뷰 체크리스트로 확인.
   - `npm run lint`, `npm run type-check`, `npm test` 통과.
3. **종료 조건(A만으로 종료 가능):** 보고서상 #175의 “단일 거대 함수” 패턴이 **재현되지 않거나**, 지표가 팀이 허용하는 수준 이하이면 **코드 변경 없이** 이슈를 닫거나 “검증 완료”로 표시한다.

### 4.2 단계 B — 조건부 얇은 분리

**트리거(하나라도 해당 시 고려):**

- 동일·유사 정적 분석에서 `initializeServices` 또는 동일 파일의 조립 구간이 여전히 임계 초과이거나,
- 리뷰에서 “반환 객체 한 블록이 가독성·테스트를 해친다”는 합의가 난 경우.

**내용:**

- 단계별로 이미 생성된 지역 변수들을 인자로 받아 `ServerServices`를 만드는 **순수 함수**(예: `assembleServerServices`)를 같은 파일 또는 `bootstrap/assemble-server-services.ts`에 둔다.
- `initializeServices`는 `await` 체인과 이 헬퍼 호출만 남긴다.
- **공개 export 변경 없음.** 테스트는 기존 통합 테스트로 회귀 검증한다(단위 테스트 추가는 선택).

## 7. 완료 정의

- 단계 A 결과가 문서화되어 있고, 필요 시 이슈가 **재현 여부**에 따라 업데이트된다.
- 단계 B를 하지 않기로 한 경우: 근거(지표 또는 리뷰)가 남아 있다.
- 단계 B를 한 경우: 동작 동일·테스트·린트·타입체크 통과.
