# Issue 287 Design - Replace Hardcoded 1GB Assumption in getMemoryMetrics()

## 1) Context and Problem

`getMemoryMetrics()` currently contains a hardcoded `1GB` total memory assumption.
This can over-report memory pressure on low-memory hosts and under-report it on high-memory hosts.

Issue #266 fixed related paths (`collectMetrics()`, `checkAlerts()`), but `getMemoryMetrics()` remained as a separate call path with the same root problem.

## 2) Scope

In scope:
- Replace hardcoded total memory with runtime system memory (`os.totalmem()`).
- Make `usagePercent` RSS-based.
- Add explicit alias field `rssUsagePercent`.
- Add additional field `heapUsagePercent`.
- Update comments/docs/tests to lock semantics.

Out of scope:
- Broad monitoring architecture refactor.
- Breaking API removal of existing fields.

## 3) Design Decision

Recommended approach (selected): compatibility-first transition.

- Keep `usagePercent` for backward compatibility.
- Define `usagePercent` semantics as RSS-based system pressure metric.
- Add `rssUsagePercent` as explicit alias for clarity.
- Add `heapUsagePercent` as supplementary metric.

Contract:
- `usagePercent === rssUsagePercent`

## 4) Architecture and Components

Single change boundary:
- `performance-monitor.ts` -> `getMemoryMetrics()`

Data sources:
- `process.memoryUsage()` -> `rss`, `heapUsed`
- `os.totalmem()` -> total system memory

Returned shape (backward-compatible extension):
- Existing fields remain.
- Added/updated semantics:
  - `usagePercent`: `rss / totalMemory * 100`
  - `rssUsagePercent`: same value as `usagePercent`
  - `heapUsagePercent`: `heapUsed / totalMemory * 100`

## 5) Data Flow

1. Call `getMemoryMetrics()`.
2. Read `rss`, `heapUsed` from `process.memoryUsage()`.
3. Read `totalMemory` from `os.totalmem()`.
4. If `totalMemory <= 0`, set all percent values to `0`.
5. Otherwise compute:
   - `usagePercent = (rss / totalMemory) * 100`
   - `rssUsagePercent = usagePercent`
   - `heapUsagePercent = (heapUsed / totalMemory) * 100`
6. Return metrics object with existing + added fields.

## 6) Error Handling and Guards

- Defensive division guard for `totalMemory <= 0`.
- Non-finite protection for percent values (`NaN`/`Infinity` -> `0`).
- No API-breaking changes in this issue.

## 7) Test Strategy

Unit tests for `getMemoryMetrics()` with mocks for `process.memoryUsage()` and `os.totalmem()`:

1. Normal case: verify `usagePercent === rssUsagePercent`.
2. Heap metric case: verify `heapUsagePercent` formula.
3. Host size variation: validate behavior under low/high `totalMemory` values.
4. Zero-memory guard: `totalMemory = 0` returns `0` percentages.
5. Compatibility check: `usagePercent` field remains present and numeric.

Test naming convention should clearly encode the semantic lock:
- "usagePercent is RSS-based"

## 8) Documentation and Comments

- Update inline comments around memory percentage calculations.
- Clarify in docs/type comments that:
  - `usagePercent` is RSS-based.
  - `rssUsagePercent` is explicit alias.
  - `heapUsagePercent` is supplementary, not primary pressure signal.

## 9) Success Criteria

- No hardcoded total memory assumption in `getMemoryMetrics()`.
- `usagePercent` reflects RSS/system-total ratio.
- `rssUsagePercent` and `heapUsagePercent` are returned correctly.
- Tests cover normal and guard cases.
- Semantics are documented to prevent regression.

## 10) Risks and Mitigations

- Risk: consumer confusion due to semantic change of `usagePercent`.
  - Mitigation: explicit alias field + comments/docs/tests locking semantics.

- Risk: duplicated fields temporarily increase response noise.
  - Mitigation: intentional transition design for compatibility.

## 11) Rollout Notes

- This is a non-breaking additive+semantic clarification change.
- Follow-up can deprecate ambiguous names after downstream adoption of `rssUsagePercent`.

## 12) 구현·코드리뷰 후속 (PR #307)

- 메모리 **예산 분모**: `process.constrainedMemory()`가 유한·양수면 우선, 아니면 `os.totalmem()` (`PerformanceMonitor` private 헬퍼).
- **`heapShareOfBudgetPercent`**: `heapUsed ÷ 예산 바이트` — **V8 `heapUsed/heapTotal` 충전률이 아님**을 필드명으로 구분.
- **`heapUsagePercent`**: `heapShareOfBudgetPercent`와 동일 값을 유지(하위 호환). 신규 소비자는 `heapShareOfBudgetPercent` 사용 권장.
- **`usagePercent`**: RSS ÷ 예산; `collectMetrics`·메모리 알림과 동일 축. 100% 초과 가능(RSS가 cgroup 한도를 넘는 관측).
- 변경 요약은 루트 `CHANGELOG.md` `[Unreleased]`에 기록.
