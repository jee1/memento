# Phase 2: http-server.ts 구조 분석

## 파일 정보
- **파일 경로**: `src/server/http-server.ts`
- **현재 크기**: 460줄
- **목표 크기**: 500줄 이하 (현재 목표 달성)

## 구조 분석

### 1. 주요 함수 및 책임

#### 1.1 서버 초기화 (`initializeServer`)
- **라인 범위**: 128-214 (약 87줄)
- **책임**:
  - 데이터베이스 초기화
  - 서비스 초기화 (부트스트랩 사용)
  - 라우터 초기화 및 등록
  - 미들웨어 설정
  - 배치 스케줄러 시작
  - 임베딩 프로바이더 정보 표시
- **의존성**: 
  - `initializeDatabase()`
  - `initializeServices()`
  - 라우터 팩토리 함수들 (`createToolsRouter`, `createAdminRouter`, 등)
  - 미들웨어 (`createServiceInjector`, `createToolContextMiddleware`, `errorHandler`)

#### 1.2 WebSocket 서버 설정 (`wss`)
- **라인 범위**: 218-395 (약 178줄)
- **책임**:
  - WebSocket 서버 생성 및 설정
  - 연결 처리 (`connection` 이벤트)
  - 메시지 처리 (`message` 이벤트)
  - 에러 처리 (`error` 이벤트)
  - 연결 종료 처리 (`close` 이벤트)
- **의존성**: `ws` 패키지 (`WebSocketServer`)

#### 1.3 서버 시작 (`startServer`)
- **라인 범위**: 397-432 (약 36줄)
- **책임**:
  - 서버 초기화 호출
  - 정리 핸들러 등록
  - HTTP 서버 리스닝 시작
- **의존성**: `initializeServer()`, `registerCleanupHandlers()`

#### 1.4 정리 핸들러 (`cleanup`, `registerCleanupHandlers`)
- **라인 범위**: 218-250 (약 33줄)
- **책임**:

  - 서비스 정리
  - 프로세스 종료 시 정리 작업

### 3. 분리 필요성 판단

#### 3.1 WebSocket 서버 설정 (144줄)
- **현재 위치**: 252-395줄
- **분리 기준**: 300줄 이상인 경우 분리 필요
- **판단**: **144줄 < 300줄** → **분리 불필요**
- **이유**: WebSocket 서버 설정이 300줄 미만이므로 분리할 필요 없음

#### 3.2 서버 초기화 로직 (87줄)
- **현재 위치**: 128-214줄
- **분리 기준**: 300줄 이상인 경우 분리 필요
- **판단**: **87줄 < 300줄** → **분리 불필요**
- **이유**: 서버 초기화 로직이 300줄 미만이므로 분리할 필요 없음

### 4. 결론

**현재 상태**: 
- 파일 크기: 460줄 (500줄 이하 목표 달성 ✅)
- WebSocket 서버 설정: 144줄 (300줄 미만, 분리 불필요)
- 서버 초기화 로직: 87줄 (300줄 미만, 분리 불필요)

**추가 분리 불필요**: 
- 모든 주요 섹션이 적절한 크기를 유지하고 있음
- 코드 구조가 명확하고 모듈화되어 있음
- 라우터는 이미 별도 파일로 분리되어 있음 (`routes/` 디렉토리)
- 미들웨어도 이미 별도 파일로 분리되어 있음 (`middleware/` 디렉토리)

**권장 사항**:
- 현재 구조 유지
- 추가 리팩토링 불필요
- Phase 2.11 작업 스킵 가능
