# Data Model (conceptual): 앵커 맵 뷰 · 검색

본 픽스는 **DB 스키마 변경 없음**. 브라우저 내 자바스크립트 상태만 기술한다.

## 앵커 맵 뷰 상태 (스펙 용어 정렬)

| 상태 | 의미 (구현 해석) |
|------|------------------|
| **empty** | `mapData` 없음, 또는 `mapData.nodes`가 비어 있어 화면에 노드가 없음 |
| **loading** | 데이터 수신·렌더 진행 중(필요 시 기존 로딩 표시와 연계; 본 픽스는 최소 변경) |
| **ready** | 렌더 가능한 노드 배열이 있고 시뮬레이션/도형이 일관된 상태 |

구현에서는 전역 `nodes`가 **항상 배열**인 불변식을 두면 `empty`/`ready` 판별이 `nodes.length === 0` vs `> 0`로 단순화된다.

## 주요 런타임 식별자

| 이름 | 타입 (개념) | 설명 |
|------|-------------|------|
| `mapData` | object \| null | 서버에서 받은 맵 페이로드(노드·링크·앵커 등) |
| `nodes` | array | D3 시뮬레이션용 노드 객체 목록; **항상 배열** |
| `links` | array | 엣지 목록; **항상 배열** |
| `searchResults` | object \| null | `search_local` 응답 파싱 결과; `items` 배열 |
| `highlightedNodeIds` | Set | 하이라이트할 메모리 ID |

## 관계

- `searchResults.items[*].id`는 `nodes[*].id`와 **부분 일치**할 수 있음(스펙과 동일).
- 검색 성공 후 맵이 **empty**이면 하이라이트 집합만 갱신하고 맵 포커스/줌은 생략 가능.

## 검증 규칙 (요약)

- `nodes`/`links`에 대해 `.find`/`.filter` 호출 전 **배열 불변식** 만족.
- 조기 반환 경로에서도 빈 배열로 동기화.
