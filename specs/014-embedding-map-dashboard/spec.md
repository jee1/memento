# Feature Specification: 기억 시각화 대시보드 (Embedding Map)

**Feature Branch**: `014-embedding-map-dashboard`  
**Created**: 2026-04-13  
**Status**: Draft  
**Input**: User description: "기억 시각화 대시보드 - 저장된 기억의 임베딩 벡터를 UMAP으로 2D 차원 축소하고 K-Means 클러스터링하여 scatter plot으로 시각화. dashboard.html에 탭으로 통합, 클릭 시 사이드 패널 표시."

## Overview

AI 개발자 및 사용자가 자신의 기억 구조를 한눈에 파악할 수 있도록, 저장된 기억의 의미적 유사도를 2D 공간에 시각화하는 대시보드 기능. 기존 관계 그래프(명시적 링크 기반)와 달리, 임베딩 벡터 기반 유사도로 자동 클러스터를 발견한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 임베딩 맵 조회 (Priority: P1)

관리자가 대시보드에 접속해 임베딩 맵 탭을 열면, 저장된 기억들이 의미적 유사도에 따라 2D 산점도에 배치되어 나타난다.

**Why this priority**: 핵심 가치를 전달하는 최소 기능. 이것 없이는 다른 기능이 의미 없음.

**Independent Test**: 대시보드 임베딩 맵 탭을 열어 기억들이 scatter plot으로 렌더링되는지 확인.

**Acceptance Scenarios**:

1. **Given** 10개 이상의 기억이 저장되어 있고, **When** 임베딩 맵 탭을 클릭하면, **Then** 각 기억이 점으로 표시된 2D 산점도가 렌더링된다.
2. **Given** 임베딩 맵이 로드 중일 때, **When** 사용자가 탭을 보면, **Then** 로딩 스피너와 "UMAP 계산 중..." 메시지가 표시된다.
3. **Given** 기억이 10개 미만일 때, **When** 임베딩 맵 탭을 클릭하면, **Then** "임베딩 맵을 그리려면 최소 10개의 기억이 필요합니다. (현재 N개)" 메시지가 표시된다.
4. **Given** 선택한 provider에 임베딩이 없을 때, **When** 임베딩 맵을 로드하면, **Then** "minilm 임베딩이 아직 없습니다. 기억을 더 저장하면 자동 생성됩니다." 메시지가 표시된다.

---

### User Story 2 - 클러스터 탐색 (Priority: P2)

사용자가 산점도에서 클러스터별로 색상 구분된 기억 분포를 보고, 의미적으로 유사한 기억 그룹을 직관적으로 파악한다.

**Why this priority**: 클러스터 시각화가 이 기능의 핵심 인사이트 제공 수단.

**Independent Test**: 산점도에서 서로 다른 색상의 점 그룹들이 보이는지, K-Means k값 변경 시 클러스터가 재편되는지 확인.

**Acceptance Scenarios**:

1. **Given** 임베딩 맵이 로드됐을 때, **When** 사용자가 산점도를 보면, **Then** 기억들이 최대 k개의 서로 다른 색상 클러스터로 구분되어 표시된다.
2. **Given** 임베딩 맵이 표시된 상태에서, **When** 마우스를 점 위에 올리면, **Then** 해당 기억의 내용 앞 80자와 기억 타입이 툴팁으로 표시된다.
3. **Given** 임베딩 맵이 표시된 상태에서, **When** k값을 변경하고 다시 로드하면, **Then** 새로운 k값으로 클러스터가 재계산되어 표시된다.

---

### User Story 3 - 기억 상세 조회 (Priority: P3)

사용자가 관심 있는 점을 클릭해 해당 기억의 전체 내용, 태그, 중요도, 생성일을 사이드 패널에서 확인한다.

**Why this priority**: 산점도에서 발견한 기억을 자세히 읽을 수 있어야 실용적 가치가 생김.

**Independent Test**: 임의의 점 클릭 시 오른쪽 사이드 패널이 열리고 기억 전체 내용이 표시되는지 확인.

**Acceptance Scenarios**:

1. **Given** 임베딩 맵이 표시된 상태에서, **When** 점을 클릭하면, **Then** 오른쪽에 사이드 패널이 슬라이드인되어 기억의 전체 내용, 태그, 중요도, 생성일이 표시된다.
2. **Given** 사이드 패널이 열린 상태에서, **When** 빈 공간을 클릭하면, **Then** 사이드 패널이 닫힌다.
3. **Given** 사이드 패널이 열린 상태에서, **When** 다른 점을 클릭하면, **Then** 사이드 패널이 새 기억의 내용으로 업데이트된다.

---

### User Story 4 - 줌/패닝 & 파라미터 조정 (Priority: P4)

사용자가 산점도를 줌/패닝하고, provider와 limit, k값을 조정해 원하는 기억 범위를 탐색한다.

**Why this priority**: 기억 수가 많을 때 탐색 편의성을 위해 필요하나, 핵심 기능은 아님.

**Independent Test**: 마우스 휠로 줌, 드래그로 패닝이 동작하는지 확인. provider 드롭다운 변경 후 재로드 시 다른 임베딩이 사용되는지 확인.

**Acceptance Scenarios**:

1. **Given** 임베딩 맵이 표시된 상태에서, **When** 마우스 휠을 스크롤하면, **Then** 산점도가 줌인/아웃된다.
2. **Given** provider 드롭다운에서 다른 값을 선택하고 Load를 클릭하면, **Then** 해당 provider의 임베딩으로 맵이 재계산된다.
3. **Given** 결과가 캐시된 상태에서, **When** 동일 파라미터로 재로드하면, **Then** "N분 전 캐시" 표시와 함께 즉시 반환된다.

---

### Edge Cases

- 기억이 10개 미만일 때: 에러 메시지 표시, scatter plot 미렌더링.
- 선택한 provider 임베딩 테이블이 비어있을 때: 안내 메시지 표시.
- 모든 기억의 임베딩 벡터가 동일할 때: 점들이 중앙에 밀집되어 표시됨 (에러 아님).
- k값이 기억 수보다 클 때: k를 기억 수로 자동 조정.
- 네트워크 오류 시: 재시도 버튼과 에러 메시지 표시.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 `/admin/embedding-map` 엔드포인트를 제공해야 한다. 파라미터: `provider` (tfidf | minilm | openai | gemini, 기본 minilm), `limit` (1~500, 기본 300), `k` (2~20, 기본 6).
- **FR-002**: 서버는 선택된 provider의 임베딩 벡터를 DB에서 로드한 뒤, UMAP으로 2D 좌표로 변환하고 K-Means로 클러스터 번호를 할당해 반환해야 한다.
- **FR-003**: 계산 결과는 서버 메모리에 최소 5분간 캐시되어야 하며, 동일 파라미터 재요청 시 캐시에서 즉시 반환해야 한다.
- **FR-004**: 임베딩된 기억이 10개 미만이면 400 오류와 사용자 친화적 메시지를 반환해야 한다.
- **FR-005**: k값이 실제 기억 수를 초과하면 k를 자동으로 기억 수로 조정해야 한다.
- **FR-006**: 대시보드에 "Anchor Map"과 "Embedding Map" 두 탭이 제공되어야 한다.
- **FR-007**: 임베딩 맵 산점도에서 점의 크기는 기억의 중요도(importance)에 비례해야 한다.
- **FR-008**: 마우스 호버 시 기억 내용 앞 80자와 타입이 툴팁으로 표시되어야 한다.
- **FR-009**: 점 클릭 시 오른쪽 사이드 패널이 열리고 기억 전체 내용, 태그, 중요도, 생성일이 표시되어야 한다.
- **FR-010**: 산점도는 마우스 휠 줌과 드래그 패닝을 지원해야 한다.
- **FR-011**: 응답에 캐시 여부와 계산 시각이 포함되어야 하며, UI에 표시되어야 한다.

### Key Entities

- **EmbeddingPoint**: 기억 하나의 시각화 데이터 — id, x좌표, y좌표, 클러스터번호, 기억타입, 전체내용, 태그목록, 중요도, 생성일시.
- **EmbeddingMapResponse**: 엔드포인트 응답 — points 배열, 메타데이터(총 수, provider, k값, 캐시여부, 계산시각).
- **EmbeddingMapCache**: 서버 인메모리 캐시 — 캐시 키(provider+limit+k), 계산 결과, 만료 시각(TTL 5분).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 300개 기억 기준 첫 로드(캐시 미스) 시 30초 이내에 시각화 결과가 화면에 표시된다.
- **SC-002**: 캐시 히트 시 임베딩 맵이 1초 이내에 렌더링된다.
- **SC-003**: 의미적으로 유사한 기억들(동일 주제)이 동일 클러스터로 그룹화되는 비율이 70% 이상이다 (수동 샘플 검증 기준).
- **SC-004**: 기억 10개 이상의 환경에서 사용자가 최초 접속 후 원하는 기억의 상세 내용을 3번의 인터랙션(탭 클릭 → 로드 → 점 클릭) 이내에 확인할 수 있다.
- **SC-005**: provider, limit, k값을 바꿔 새 맵을 로드하는 조작이 5번의 클릭 이내에 완료된다.

## Assumptions

- 사용자는 관리자 권한을 가진 것으로 가정 (기존 Admin API Key Bearer 인증 재사용).
- UMAP 라이브러리로 `umap-js` (npm) 사용.
- K-Means는 외부 라이브러리 없이 Lloyd's algorithm을 직접 구현 (최대 100 iteration).
- 프론트엔드 렌더링은 D3.js v7 (CDN, 기존 코드와 동일) 사용.
- 임베딩 벡터가 없는 기억은 시각화에서 제외 (오류 아님).
- 캐시는 서버 재시작 시 초기화됨 (영속성 불필요).
- 기존 `dashboard.html`의 Anchor Map 기능은 변경 없이 유지.
