# Contract: LLM 추출기 가용성 판정

**Feature**: 656-819-fix-llm-init-race | **Date**: 2026-08-25

## 1. MCP 도구 계약 — 변경 없음

`extract_relations` 의 요청 파라미터·응답 필드·오류 형태는 그대로다(FR-006, 헌법 II).

| 항목 | 상태 |
|------|------|
| 요청 파라미터(`memory_id`, `force`, …) | 불변 |
| 응답 필드(`extracted_count`, `relations[]`, …) | 불변 |
| `method` 옵션 의미(`rule` / `llm` / `hybrid`) | 불변 |

**관찰 가능한 행동 변화**(계약 변경 아님, 결함 수정):
- LLM 이 설정된 환경에서 `hybrid` 응답에 `method: 'llm'` 관계가 실제로 포함되기 시작한다.
- `method: 'llm'` 요청이 초기화 타이밍 때문에 실패하지 않는다.

## 2. 추출기 가용성 판정 계약 (내부)

FR-009: **가용성 판정의 공개 경로는 초기화 완료를 보장하는 비동기 판정 하나다.**

| 판정 | 계약 | 호출자 |
|------|------|--------|
| 비동기 가용성 판정 | 진행 중인 초기화가 끝난 뒤의 결과를 반환한다. 초기화가 실패했더라도 예외를 던지지 않고 "사용 불가"를 반환한다(FR-004). | `RelationExtractor` 의 두 판정 지점 |
| 동기 가용성 판정 | **초기화 완료 이후에만 유효.** 유지하되 문서에 이 제약을 명시하고, 새 외부 호출자를 만들지 않는다. 비동기 판정이 이 함수에 위임하므로 기존 테스트 시드는 유지된다. | 내부 위임 + 기존 테스트 |

**검증 방식**: FR-009 는 런타임 시나리오가 아니라 **정적으로** 확인한다 — 초기화 완료를 보장하지 않는 판정에 대한 외부 호출자가 0인지 확인한다.

## 3. 판정 일관성 계약

FR-010: 가용성 판정과 실행 경로의 프로바이더 판정은 같은 기준을 쓴다.

| 상황 | 가용성 판정 | 실행 경로 | 요구 |
|------|-------------|-----------|------|
| 클라우드 프로바이더 설정 | 사용 가능 | 동일 | 이미 일치 |
| 명시적 로컬 프로바이더 설정 | 사용 가능 | 동일 | 이미 일치 |
| 자동 선택으로 로컬 프로바이더 채택 | 사용 가능 | **사용 불가** | **수정 대상** — 두 판정 모두 사용 가능이어야 한다 |

"사용 가능"으로 판정된 뒤 실행 단계에서 "사용 가능한 프로바이더 없음"으로 실패하는 조합이 있어서는 안 된다.

## 4. 동시성 계약

FR-001: 한 추출기 인스턴스의 초기화 완료를 동시에 기다리는 추출들은 **모두 같은 초기화 결과**를 본다. 배치 추출은 한 인스턴스가 처리하므로 이 계약으로 커버된다.

인스턴스 간 일치는 계약이 아니다 — 요청별 인스턴스 생성을 유지하므로(Non-Goals) 인스턴스마다 초기화가 독립적이다.

## 5. 지연 계약

| 경로 | 대기 |
|------|------|
| 규칙 기반 결과가 신뢰도 임계값을 만족 | **대기 없음**(FR-007). 가용성 판정 자체를 하지 않는다 |
| 기억 저장 경로의 관계 추출 | 저장 응답과 분리된 백그라운드 작업 → 저장 응답 시간 변화 없음 |
| 명시적 관계 추출 도구 호출 | 초기화 완료까지 대기. 상한은 기존 초기화 재시도 정책이 정하며 새 설정값을 두지 않는다(FR-008) |
