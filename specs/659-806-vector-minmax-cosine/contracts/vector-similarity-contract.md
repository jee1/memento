# Contract: 벡터 유사도 (issue #806, #713)

**Status**: 이 계약은 새로 만들어지는 것이 아니라 **이미 기준 문서에 기술되어 있고 코드가 어긴 것**이다. 이번 작업은 코드를 계약에 맞춘다.

**Scope**: `packages/memento-core`가 검색 결과에 실어 내보내는 근접도 값. MCP `recall` 응답과 내부 랭킹 입력 모두 해당한다.

---

## C1. 값 정의

```
similarity = clamp(1 − cosine_distance, 0, 1)
비유한 distance → similarity = 0
```

- 정의는 저장소 전체에 **하나만** 존재한다. 경로별 재구현 금지.
- 모든 `vec0` 테이블은 `distance_metric=cosine`으로 생성된다. metric을 생략하면 L2가 적용되어 이 계약이 깨진다.

## C2. 값 성질

| # | 성질 | 위반 시 증상 |
|---|------|--------------|
| C2-1 | [0, 1] 범위의 유한값 | 임계값·슬롯 판정이 예측 불가 |
| C2-2 | 클수록 가깝다 | 정렬·임계값·표시가 전부 반전 |
| C2-3 | 결과셋 구성과 무관 | 무관한 결과가 만점을 받음 |
| C2-4 | 후보 1건과 다건에서 동일 | 결과 수에 따라 같은 기억의 점수가 달라짐 |

## C3. 노출 형태

| 항목 | 계약 |
|------|------|
| 필드 이름·타입 | 변경 없음 |
| 값 범위 | [0, 1] 유지 |
| 근접도 필드 수 | **1개.** 같은 양을 반대 방향으로 담은 필드를 함께 두지 않는다 |
| 값 분포 | **달라진다.** 교정 전에는 최상위가 항상 최댓값이었다 |

## C4. 소비자가 지켜야 할 것

| 소비자 | 계약 |
|--------|------|
| 하이브리드 벡터 임계값 | 절대 유사도로 판정하며, 어떤 재조정보다 **앞서** 수행 |
| 보충 동작 | 채워진 후보도 자기 절대 점수를 유지 |
| 중복 제거 | 제공자 간 최댓값 채택 |
| 앵커 슬롯(A 0.8 / B 0.6 / C 0.4) | 절대 유사도 기준 |
| 설명 문구 | 절대 유사도 기준으로 선택. 표시 숫자는 점수 필드와 일치 |
| 결합 공식 | 기존 계약 유지(결합값 보존, 0을 결측으로 취급하지 않음) |

## C5. 경로 계약

| 경로 | 척도 | 조회 범위 |
|------|------|-----------|
| 정상 | C1 | 저장된 모든 제공자 |
| 대체 | C1 (동일) | 쿼리 임베딩 제공자 1개 |

두 경로의 **척도는 같아야 하고**, 조회 범위 차이는 계약 위반이 아니다. 경로 간 값 비교는 제공자를 맞춘 뒤 수행한다.

## C6. 계약 변경 기록

점수 산출 방식이 달라지면:
1. 랭킹 버전 식별자가 달라져야 한다(기계 판독 구분).
2. 기준 문서 `docs/agents/search-ranking.md`에 시점과 해석 기준을 남긴다(사람 판독 구분).

저장된 점수 스냅샷의 마이그레이션·백필은 하지 않는다.
