    기억 보존 결정 대기열

    이건 뭔가요

    중요도가 높은데 오랫동안 recall 되지 않아 자동 망각으로 향하는 기억들입니다. 각 기억을 보존할지 무시할지 결정하는 자리입니다. 결정하지 않으면 기억은 그대로 망각 경로에 남습니다. 검토 대기열 후보 선정 배치가 후보를 채웁니다.

    결정하는 법: 목록에서 행을 선택해 미리보기로 내용을 확인한 뒤 결정합니다. 보존은 이 기억의 마지막 접근 시각을 지금으로 갱신해 자동 망각에서 멀어지게 합니다. 무시는 후보만 대기열에서 내리고 기억은 그대로 둡니다 — 망각 경로도 그대로입니다. 여러 건은 체크박스로 골라 일괄 무시·만료 할 수 있습니다.

    대기열 진단 (지표·최근 샘플·수동 배치 실행)

    대기열 상태

    롤링 윈도우는 행의 생성·보존·무시 시각을 쓰고, 만료는 갱신 시각 기준입니다.

    최근 샘플

    샘플 시각 (UTC) 대기 순유입 1h 생성 1h 처리 1h

    수동 배치 실행

    이 서버 프로세스의 최근 POST /admin/batch/run 호출 (메모리 내; 재시작 시 초기화).

    아직 기록된 수동 배치 실행이 없습니다.
    완료 (로컬) 작업 유형 성공 소요 시간 처리 오류 / 메모
    대체 후보 승인 (옛 기억을 새 기억으로 바꿀지 정합니다)

    LLM 이 같은 범위의 옛 기억과 새 기억 쌍을 판정해 남긴 후보입니다. 승인하면 옛 기억의 읽기 경로가 새 기억으로 넘어갑니다. 거절하면 같은 쌍은 다시 목록에 뜨지 않습니다.

    상태 판정 프로젝트 옛 본문 새 본문

    선택: 이 탭이 백그라운드일 때 대기열이 늘면 시스템 알림을 받습니다. 알림에는 건수만 포함되며 기억 내용은 포함되지 않습니다.

      배치 작업
      
            
      
              이건 뭔가요
              
      
                
      
                  스케줄 표, 메모리 내 큐 스냅샷, durable 실행 이력, 실행 로그.
                  일시정지 / 재개 / 지금 실행 / 재시도는 확인 대화상자를 사용하며, 수동 새로고침만 지원합니다.
                
      
                
      데이터 출처
      
                
        
                  
      • 작업 실행은 job_run / job_run_log에 보존됩니다.
        • 
                  
      • 실행 타임라인: GET /admin/batch/runs (durable; 행 선택 시 로그)
        • 
                  
      • 실행 로그: GET /admin/batch/runs/:runId/logs (수동 새로고침; SSE 없음)
        • 
                  
      • 수동 실행 이력: GET /admin/batch/run-history (process-local 링 버퍼, 보조; POST /admin/batch/run만)
        • 
                
      
                
      등록 배치 역할
      
                
      새로고침 후 GET /admin/batch/stats의 jobs[].description과 동일한 요약입니다.
